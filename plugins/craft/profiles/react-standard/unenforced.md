**Every property below is unenforced.** Nothing here fails a build, no
tool reports on it, and none of it is a rule — it is what the Craft
register holds that this profile could not install, written out so that
an assistant reading this repository knows what is expected of the code
and knows that nothing is checking.

Generated by `craft-install` from the Craft register. Re-run it rather
than editing here — a hand edit is what the next run reports.

## Judgment only (20)

Nothing can decide these but a person. They are the half of *well-made* a linter has no
access to, and a rule claiming otherwise would be worse than the silence.

### `any.authenticate-non-public-endpoints`

Every non-public endpoint authenticates.

### `any.authorise-separately-from-authenticate`

Permission is checked as well as identity.

**Why nothing checks it:** Bucket 3, and **the single most consequential property in
this register and the least checkable.** Recorded rather than dropped, because the
residue is what the installer hands back as prose labelled unenforced, and this is the
row that label exists for.

### `any.conditional-requests`

Frequently polled resources support `ETag`.

### `any.correlation-id-propagated`

A request id is present in every response and traced through.

**Why nothing checks it:** Bucket 3. The header is checkable; propagation is not.

### `any.http-method-semantics`

Methods carry their standard meanings and idempotency.

**Why nothing checks it:** Bucket 3. The spelling is checkable; the semantics are not.

### `any.json-merge-patch`

Partial updates use RFC 7396.

### `any.secret-rotation`

Secrets rotate on a schedule and on compromise.

**Why nothing checks it:** Bucket 3. A process, not a code property.

### `any.security-audit-logging`

Security-relevant events are logged.

### `any.threat-modelling`

New features handling sensitive data are threat modelled.

**Why nothing checks it:** Bucket 3, and arguably not a code rule at all. S2 flagged it
as a candidate for removal at S4; **it is kept**, because removing a row is a claim that
the property does not matter and the register's own answer is that it matters and cannot
be checked here.

### `any.validate-at-boundaries`

Input is validated at the system boundary.

### `react.a11y-link-purpose`

A link's purpose is clear from its text.

**Why nothing checks it:** `jsx-a11y/anchor-ambiguous-text` is `off` in `recommended`
and false-positives on legitimate copy. **Half the stated reason no longer holds** —
C5's probe showed 6.10.2 reading the `aria-label` — and the other half stands, so the
row is kept unenforced with the measurement rather than the assumption behind it.

### `react.barrel-exports`

Modules are re-exported through an `index.ts`.

**Why nothing checks it:** **Contested by decision, and it stays that way.** Widely
argued against on bundle and circular-import grounds; inverting it needs a source
arguing for the inversion and none is registered. The register cites; it does not opine.

### `react.discriminated-unions`

State and API responses are modelled as discriminated unions.

### `react.domain-error-types`

Domain failures have their own error types.

### `react.no-effect-chains`

One effect does not exist to react to another effect's state write.

**Why nothing checks it:** Bucket 3. `set-state-in-effect` catches the consequence; the
shape is a judgement.

### `react.no-event-logic-in-effect`

Logic belonging to an event handler is not moved into an effect.

### `react.no-fetch-in-effect`

Data fetching goes through a framework or a library, not a bare effect.

**Why nothing checks it:** Bucket 3. *You Might Not Need an Effect* stops short of a
rule here and recommends a mechanism.

### `react.readonly-immutability`

Properties and arrays that should not change are `readonly`.

**Why nothing checks it:** Bucket 3. `prefer-readonly` covers private class fields only,
which is not the property.

### `react.state-reset-by-key`

State is reset by remounting on a `key`, not by an effect watching a prop.

### `react.test-behaviour-not-implementation`

A test asserts what the user experiences, not how it is built.

**Why nothing checks it:** Bucket 3. The plugin enforces the mechanics; the principle is
judgement.

## A check could hold these, and none is written (25)

Enforceable in principle, at a cost nobody has paid. They are the list a later profile
version is drawn from, and until then they are yours.

### `any.adaptive-password-hashing`

Passwords use bcrypt, Argon2 or scrypt.

**Why nothing checks it:** Per-stack, and asymmetric: `python.no-insecure-hash` catches
the negative and nothing asserts the positive.

### `any.changelog-maintained`

A changelog is updated as part of release.

**Why nothing checks it:** A check that the file moved with the tag could hold it.
Nothing registered does.

### `any.documented-endpoints`

Every endpoint has request and response schemas and examples.

**An instrument exists:** `spectral`. `spectral` over an OpenAPI document would assert
it.

### `any.explicit-api-version`

The API version is explicit from the first release.

**An instrument exists:** `spectral`. `spectral` over an OpenAPI document would assert
it.

### `any.explicit-cors`

CORS origins are explicit, never `*` with credentials.

**An instrument exists:** an infrastructure analyser. Checkable in infrastructure code
or in configuration.

### `any.filter-and-sort-documented`

Collection query parameters are documented.

**An instrument exists:** `spectral`. `spectral` over an OpenAPI document would assert
it.

### `any.health-endpoint`

A health endpoint reports service and dependency state.

**An instrument exists:** `spectral`. `spectral` for its presence, and for nothing about
its truthfulness.

### `any.https-everywhere`

HTTP is rejected or redirected; HSTS is set.

**An instrument exists:** an infrastructure analyser. Checkable in infrastructure code
where the listener is declared. IAC-001 is adjacent.

### `any.imperative-commit-subject`

A commit subject is imperative present tense.

**Why nothing checks it:** Nothing asserts it reliably. A word-list check would be a
heuristic.

### `any.iso8601-datetimes`

Date and time fields are ISO 8601 strings.

**An instrument exists:** `spectral`. `spectral`, against a format assertion.

### `any.location-header-on-created`

A 201 carries a `Location`.

**An instrument exists:** `spectral`. `spectral` over an OpenAPI document would assert
it.

### `any.paginated-collections`

No collection endpoint returns an unbounded list.

**An instrument exists:** `spectral`. `spectral` over an OpenAPI document would assert
it.

### `any.plural-collections`

Collections are plural, items are addressed by id.

**An instrument exists:** `spectral`. `spectral` over an OpenAPI document would assert
it.

### `any.pull-request-description`

A pull request says what changed, why, and how to verify.

**Why nothing checks it:** A template exists; a check that it was filled in does not.

### `any.rate-limit-sensitive-endpoints`

Authentication and sensitive writes are rate limited.

**An instrument exists:** an infrastructure analyser. Checkable in infrastructure code
where the limit is declared.

### `any.rest-resource-nouns`

Paths name resources, not actions.

**An instrument exists:** `spectral`. `spectral` over an OpenAPI document would assert
it.

### `any.security-response-headers`

CSP, `nosniff`, frame options and referrer policy are set.

**An instrument exists:** an infrastructure analyser. Checkable in infrastructure code,
or in a response test at a different locus.

### `any.small-pull-requests`

A pull request is reviewable in under thirty minutes.

**Why nothing checks it:** A diff-size threshold could hold it and the number would be
arbitrary. No source in the register proposes one.

### `any.standard-status-codes`

Responses use the conventional status codes.

**An instrument exists:** `spectral`. `spectral`, against a declared set of status
codes.

### `any.structured-error-body`

Errors carry a code, a message and a correlation id.

**An instrument exists:** `spectral`. `spectral`, against a shared error schema.

### `react.a11y-contrast`

Text meets the contrast minimum.

**Why nothing checks it:** **Nothing static asserts it.** Contrast is a rendered-pixel
property; it needs an axe run in a browser, which is a different instrument at a
different locus.

### `react.async-await-over-chains`

`async`/`await` rather than `.then()` chains.

**Why nothing checks it:** Nothing in the registered plugins. `eslint-plugin-promise`'s
`prefer-await-to-then` would assert it, and that source is registered without the rule
being taken.

### `react.external-store-subscription`

An external store is read through `useSyncExternalStore`.

**Why nothing checks it:** Nothing asserts it. A check could look for `useEffect` beside
`subscribe`; none is registered.

### `react.no-direct-component-calls`

A component is used in JSX, never called as a function.

**Why nothing checks it:** Nothing names it directly. `rules-of-hooks` catches the hook
consequence of calling a component, not the call.

### `react.no-hooks-as-values`

A hook is not passed around as a value.

**Why nothing checks it:** Nothing in the registered plugins asserts it.

## An instrument exists, and this profile does not install it (4)

Either it was measured and demoted — the reason is with it, and it is the reason not to
re-enable it — or nothing has measured it and ADR 0051's third precondition is unmet.

### `any.commit-references-work-item`

A commit body or footer names the work item.

**An instrument exists:** commitlint `references-empty`. The same group and the same
cost as `any.conventional-commits`.

### `any.commit-subject-length`

A subject fits in 72 characters.

**An instrument exists:** commitlint `header-max-length`, or commitizen
`message_length_limit`. The same group and the same cost as `any.conventional-commits`.

### `any.conventional-commits`

Commit subjects follow `type(scope): description`.

**An instrument exists:** commitlint with @commitlint/config-conventional, or commitizen
`cz check`. The instrument exists and the group is simply on — every repository has
commit messages, so there is no artefact whose absence makes the property inapplicable.

### `react.naming-form`

PascalCase for types and components, camelCase for values.

**Why nothing checks it:** `@typescript-eslint/naming-convention` is in no recommended
preset and requires a written selector list, which is a configuration nobody here has
agreed. Python's counterpart is enforced because `pep8-naming` needs no such list.

## Recorded elsewhere, and not yours to check (12)

Listed by name only. Each is either satisfied by a choice this profile
already made, or owned by a control or a gate that runs without you.

- `any.branch-naming` — Branches read `type/short-description`. Owned by profile.
- `any.ci-green-before-merge` — Every check passes before merge. Owned by control.
- `any.delete-merged-branches` — Branches are deleted after merge. Owned by profile.
- `any.dependency-vulnerability-scanning` — Known CVEs in dependencies are surfaced.
  Owned by control.
- `any.linear-merged-history` — Merged history contains only logical commits. Owned by
  profile.
- `any.no-direct-push-to-default` — Nothing lands on the default branch outside a pull
  request. Owned by control.
- `any.no-secrets-in-vcs` — No credential is committed. Owned by control.
- `any.semver-release-tags` — Releases are tagged `vMAJOR.MINOR.PATCH`. Owned by
  profile.
- `any.signed-commits` — Commits are signed where policy requires. Owned by profile.
- `react.jsx-runtime-assumed` — `React` need not be in scope for JSX. Owned by the
  profile's own base choice.
- `react.no-legacy-proptypes` — Prop types are types, not runtime `propTypes`. Owned by
  the profile's own base choice.
- `react.strict-type-checking` — `tsconfig` enables the strict family. Owned by control.
