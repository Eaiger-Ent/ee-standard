**Every property below is unenforced.** Nothing here fails a build, no
tool reports on it, and none of it is a rule — it is what the Craft
register holds that this profile could not install, written out so that
an assistant reading this repository knows what is expected of the code
and knows that nothing is checking.

## Judgment only (22)

Nothing can decide these but a person. They are the half of *well-made* a linter has no
access to, and a rule claiming otherwise would be worse than the silence.

### `any.authenticate-non-public-endpoints`

Every non-public endpoint authenticates.

### `any.authorise-separately-from-authenticate`

Permission is checked as well as identity.

**Why nothing checks it:** Bucket 3, and **the single most consequential property in
this register and the least checkable.** Recorded rather than dropped, because the
residue is what the installer hands back as prose labelled unenforced, and this is the
row that label exists for.

### `any.conditional-requests`

Frequently polled resources support `ETag`.

### `any.correlation-id-propagated`

A request id is present in every response and traced through.

**Why nothing checks it:** Bucket 3. The header is checkable; propagation is not.

### `any.http-method-semantics`

Methods carry their standard meanings and idempotency.

**Why nothing checks it:** Bucket 3. The spelling is checkable; the semantics are not.

### `any.json-merge-patch`

Partial updates use RFC 7396.

### `any.secret-rotation`

Secrets rotate on a schedule and on compromise.

**Why nothing checks it:** Bucket 3. A process, not a code property.

### `any.security-audit-logging`

Security-relevant events are logged.

### `any.threat-modelling`

New features handling sensitive data are threat modelled.

**Why nothing checks it:** Bucket 3, and arguably not a code rule at all. S2 flagged it
as a candidate for removal at S4; **it is kept**, because removing a row is a claim that
the property does not matter and the register's own answer is that it matters and cannot
be checked here.

### `any.validate-at-boundaries`

Input is validated at the system boundary.

### `python.abstraction-ordering`

Functions read high-level first, details after.

**Why nothing checks it:** Bucket 3: an ordering judgement.

### `python.composition-over-inheritance`

Behaviour is extended by composition unless the relation is genuinely *is-a*.

### `python.depend-on-abstractions`

Cross-module dependencies are on abstractions.

### `python.dependency-injection`

Dependencies are provided, not constructed in place.

### `python.exception-carries-context`

An error type or message adds information the caller did not have.

**Why nothing checks it:** Bucket 3 by its own classification: whether a message carries
context is a judgement.

### `python.minimal-test-setup`

Fixtures and setup stay small.

### `python.naming-intent`

A name says what the thing is for.

**Why nothing checks it:** Bucket 3. E741 catches three ambiguous single letters and
nothing else, which is not the property.

### `python.no-mocking-domain-logic`

Test doubles stand in for external dependencies, not for the code under test.

### `python.self-documenting-code`

Code needs few comments because it reads clearly.

### `python.single-responsibility`

A unit has one reason to change.

**Why nothing checks it:** Bucket 3: the principle, not a countable property.

### `python.test-arrange-act-assert`

A test's setup, action and assertion are visually distinct.

### `python.test-naming`

A test name states the scenario and the expected outcome.

**Why nothing checks it:** Bucket 3. pytest's test_ prefix is collection, not naming
quality.

## A check could hold these, and none is written (28)

Enforceable in principle, at a cost nobody has paid. They are the list a later profile
version is drawn from, and until then they are yours.

### `any.adaptive-password-hashing`

Passwords use bcrypt, Argon2 or scrypt.

**Why nothing checks it:** Per-stack, and asymmetric: `python.no-insecure-hash` catches
the negative and nothing asserts the positive.

### `any.changelog-maintained`

A changelog is updated as part of release.

**Why nothing checks it:** A check that the file moved with the tag could hold it.
Nothing registered does.

### `any.explicit-api-version`

**An instrument exists:** `spectral`. `spectral` over an OpenAPI document would assert

### `any.pull-request-description`

### `any.rate-limit-sensitive-endpoints`

### `any.rest-resource-nouns`

### `any.security-response-headers`

### `any.small-pull-requests`

### `any.standard-status-codes`

Responses use the conventional status codes.

**An instrument exists:** `spectral`. `spectral`, against a declared set of status

### `any.structured-error-body`

Errors carry a code, a message and a correlation id.

**An instrument exists:** `spectral`. `spectral`, against a shared error schema.

### `python.class-dependency-count`

A class depends on few collaborators.

**Why nothing checks it:** Nothing asserts it. Countable from `__init__` parameters,
which is PLR0913 at a different site.

### `python.no-duplication`

The same logic is not written twice.

**Why nothing checks it:** Nothing in ruff. A clone detector could hold it, at the cost
of a second tool and a threshold no source agrees on.

### `python.no-flaky-tests`

A test that does not pass consistently is fixed or deleted.

**Why nothing checks it:** Nothing asserts it. Repeated runs detect it; nothing prevents
it.

### `python.no-log-and-reraise`

An error is logged **or** re-raised, not both.

**Why nothing checks it:** Nothing in the register asserts it. TRY400 and TRY401 are
adjacent and cover a different mistake.

### `python.no-sensitive-data-in-logs`

Secrets and PII never reach a log.

**Why nothing checks it:** Nothing asserts it. A denylist over log call arguments could,
at the cost of a list nobody here can validate.

### `python.shallow-inheritance`

Inheritance hierarchies stay shallow.

**Why nothing checks it:** Nothing asserts it. Depth is mechanically countable and
nothing counts it.

### `python.test-code-quality`

Test code is held to the same standard as production code.

**Why nothing checks it:** Configuration rather than a rule: whether the lint profile
applies to tests/ at all. It does — there is no per-file-ignores section anywhere in
this profile, and the two scoped properties are scoped rather than excused.

### `python.test-independence`

Tests do not depend on order or shared mutable state.

**Why nothing checks it:** Nothing asserts it. A randomised-order run detects violations
empirically; nothing prevents them.

## An instrument exists, and this profile does not install it (5)

Either it was measured and demoted — the reason is with it, and it is the reason not to
re-enable it — or nothing has measured it and ADR 0051's third precondition is unmet.

### `any.commit-references-work-item`

A commit body or footer names the work item.

**An instrument exists:** commitlint `references-empty`. The same group and the same
cost as `any.conventional-commits`.

### `any.commit-subject-length`

A subject fits in 72 characters.

**An instrument exists:** commitlint `header-max-length`, or commitizen
`message_length_limit`. The same group and the same cost as `any.conventional-commits`.

### `any.conventional-commits`

Commit subjects follow `type(scope): description`.

**An instrument exists:** commitlint with @commitlint/config-conventional, or commitizen
`cz check`. The instrument exists and the group is simply on — every repository has
commit messages, so there is no artefact whose absence makes the property inapplicable.

### `python.exception-type-carries-its-message`

A long message belongs to an exception type, not to the raise site.

**Why nothing checks it:** C5 demoted the only candidate. TRY003 fires only where EM101
or EM102 already fires, and EM101's own remedy silences it while the message stays
outside the exception class — a rule satisfied without the property being satisfied.

### `python.return-count`

A function has few exit points.

**Why nothing checks it:** **Incompatible, permanently.** An early return is the
recommended fix for clean-code 102's nesting and increments PLR0911's count, so the two
cannot both hold. The only such pair in this register.
